# 執筆の手引き（章を新しく書く人へ）

## 必ず最初に読むもの
1. `content/chapters/06_未来の作戦マップ.md` … 構成・文体・workブロックの手本
2. `content/chapters/07_3年後のチーム図と役割の約束書.md` … form / orgchart など表の多い章の手本
3. `docs/02_用語の言い換え表.md` … 用語は必ず新しい呼び名を使う
4. `content/example/company.md` … 記入例の架空企業「ひだまりケア株式会社」。正解データ・追加設定と必ず一致させる
5. `docs/03_挿絵のルール.md` と `assets/img/kururin.svg`・`ch06-cover.svg`・`ch06-structure.svg` … 挿絵のルールと見本
6. `README.md` の「入力欄（ワーク）の書き方」… 使える type と設定

## 絶対ルール
- 旧資料（Excel）の文章・質問文・診断項目は**転載しない**。考え方だけ参考にし、オリジナルで書き直す。質問は本当に必要なものに絞る
- 旧資料に書かれた記入内容・実在の人名・会社名・ブログ記事・他社事例（ザッポス、スーパーホテル、トヨタなど）は使わない
- 記入例はすべて架空企業「ひだまりケア株式会社」。人物は company.md にいる人だけ（必要なら「パートのAさん」など名前のない表現）
- 文体：矢部大の語り口。一人称「私」。です・ます調。経験談ベース（「私が社長さんとお話ししていて気づいたのは〜」）。上から目線にしない、一緒に走るパートナーの温度感
- 小学生でもわかる言葉と、身近なたとえ話（学校・スポーツ・料理・家族など）。カタカナ専門用語は避け、使う場合は `> 💡 専門用語では〇〇といいます。` の形で一度だけ添える
- 太字 `**〜**` はOK

## 章の構成（必ずこの順）
frontmatter（id, title, cover, subtitle, stage, required: false, minutes, output, uses, provides）

① この章でできるようになること
② なぜ必要なの？（`### こんなこと、ありませんか？` の箇条書き5つ前後 → 私の気づき → `### 目指す姿`）
③ 考え方（`### 1. 〜` の番号つき小見出し5〜8個、表・たとえ話・✕◯の比較、合計3000〜4500字）
④ ワーク（` ```work ` ブロック。6〜12問。各問に hint と example を必ず。前の章の答えを使うときは display で表示）
⑤ できあがるもの
⑥ セルフチェック（`- [ ]` で5項目）
⑦ 次の章へ
⑧ 講師ガイド（ねらい・事前準備・時間配分表・問いかけの例・よくあるつまずき表）

## workブロックで使える type（これ以外は使わない）
text / textarea / number / date / select / checklist / table（columns, rows, min_rows, max_rows, from, source）/ form（fields, repeat。fieldの type は text / textarea / list / table / signature）/ orgchart / scale（scale, groups。点数診断）/ mandala / display（source）

- id は `NN.〇〇` の形で章番号から始める（例 `13.message`）。サイト全体で重ならないこと
- 前の章を参照できる主なID：`01.purpose` `01.values` `04.values` `05.vision.oneline` `05.customer` `06.so` `06.ksi` `07.roles` `07.contracts` `09.meetings`

## 挿絵（各章に2〜3枚）
- `assets/img/chNN-cover.svg`（扉絵 800×320。くるりんがひとこと話す）を frontmatter の `cover:` に
- 図解を1〜2枚（`chNN-xxxx.svg`）。考え方の中のいちばん大事な仕組み・流れを絵にして `![説明](assets/img/chNN-xxxx.svg)` で入れる
- ` ``` ` で文字の図を描かない（必ずSVGにする）
- 書いたら `python -c "import xml.dom.minidom,sys;xml.dom.minidom.parse(sys.argv[1])" ファイル` でXMLチェック
