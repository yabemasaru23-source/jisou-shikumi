# 会社が自走する仕組みづくり 学習コンテンツ 設計書（v0.2）

作成日：2026-09-30
対象：仕組み経営（識学は別コンテンツとして後日）

---

## 1. この設計書の目的

旧「仕組み経営導入パッケージワークシート（Excel・68シート）」を、**一般の経営者が一人でも迷わず進められる学習コンテンツ**に作り直すための設計図です。
内容はすべて**オリジナルの文章で書き直し**、旧資料に記入されていた事例や個人の回答は一切使いません。

---

## 2. 旧Excelの問題点（読み込み結果）

| # | 問題 | 具体例 |
|---|---|---|
| 1 | **量が多すぎる** | 68シート、約5.6万文字。カリキュラムは36項目 |
| 2 | **ゴミシートが混在** | 「回復済み_Sheet1〜23」が23枚。何のシートか名前でわからない |
| 3 | **「なぜやるのか」が書かれていない** | 質問だけが並び、考え方は別の動画・テキストに頼っている |
| 4 | **同じ質問が何度も出る** | 「理想の顧客」をビジョン・ブランド・ポジショニング・集客で4回聞いている |
| 5 | **前の成果が次につながらない** | ビジョン→SO→KSI→組織図→職務契約書が本来一本の線なのに、毎回ゼロから書く |
| 6 | **ゴールが見えない** | 1枚ごとの所要時間、完成形、良し悪しの基準（チェック）がない |
| 7 | **全部やる前提** | 36項目すべてが同じ重さ。どれが必須でどれが選択なのかわからない |

## 3. 作り直しの基本方針（5原則）

1. **一本の道にする**：「自分 → 会社の軸 → 戦略 → 仕組み」の順に、前の章の完成物が次の章の材料になる構成
2. **必修と選択を分ける**：まず**必修8章**だけで「会社の設計図」が完成する。残りは必要に応じて選ぶ
3. **1章＝同じ型**：どの章も「なぜ → 考え方 → ワーク → 完成物 → セルフチェック」の5ブロックで統一
4. **1回で書いたら使い回す**：ビジョン・顧客像・KSIなどは一度入力すれば、後の章に自動で表示される
5. **記入例は架空の1社で通す**：全章を同じ架空企業の例で見せるので、つながりが理解しやすい

## 5. 1章の標準フォーマット（全章共通）

```
┌─────────────────────────────────────┐
│ ① この章でできるようになること（3行）   │ ← ゴールを先に見せる
│ ② なぜ必要か（困りごと → 目指す状態）    │ ← 経営者の「あるある」から入る
│ ③ 考え方（図1枚＋解説 800〜1500字）      │ ← ここがオリジナル教材の中心
│ ④ ワーク（3〜7問・1問ずつ入力）          │ ← 各問に「ヒント」「記入例」つき
│ ⑤ 完成物（入力内容から自動でまとまる）    │ ← そのまま印刷・共有できる
│ ⑥ セルフチェック（5項目）                │ ← 良し悪しの基準
│ ⑦ 次の章とのつながり                     │
│ ⑧ 講師ガイド（セミナーでの進め方）        │ ← 時間配分・問いかけ例・つまずきポイント
└─────────────────────────────────────┘
```

### セルフチェックの例（第6章 未来の作戦マップ）
旧資料の添削メモにあった観点を、誰でも使えるチェック項目にします。
- [ ] 3年後の目標（SO）は**1つ**に絞れているか（売上・粗利・経常利益のどれか1つ）
- [ ] 目標は「いつまでに・何を・いくつ」が明確か（SMART）
- [ ] 8つのテーマは「活動テーマ（上段）」と「指標1つ（下段）」に分かれているか
- [ ] 財務・顧客・業務・人材の4つの視点に抜けはないか
- [ ] 「この8つを達成すれば3年目標が達成できる」とストーリーで説明できるか

## 6. 章をまたいで引き継がれるデータ（つながりの設計）

一度入力すれば後の章に自動表示されるので、「前に書いたことをまた書く」がなくなります。

```
第1章 人生の目的 ──┐
第4章 価値観 ──────┼──→ 第13章 採用（求める人物像）／第15章 育成／第16章 ブランド
第5章 ビジョン ────┴──→ 第6章 未来の作戦マップの出発点
第6章 SO（3年目標）──→ 中央に表示
       KSI 8テーマ ──→ 第7章 組織図の部門・役職の候補
       仕組み64個 ───→ 第8章 仕組み一覧表の初期データ
第7章 役職と職務契約書 → 第13章 採用計画／第14章 オンボーディング
第5章「顧客像」（1回だけ定義）→ 第16・17・18章で再利用
全章の完成物 ─────→ 第11章「会社の取扱説明書（運営マニュアル）」の目次に自動で並ぶ
```

## 7. 記入例用の架空企業（全章共通）

実在の企業・人物は使わず、1社の架空企業で全章の記入例を作ります。

> **（案）ひだまりケア株式会社**
> 地方都市で訪問介護とデイサービスを営む。社員35名。創業12年。社長が現場にも入っており、
> 「社長がいないと回らない」状態からの脱却を目指している。

※業種は変更できます（例：工務店、整骨院、飲食店、士業事務所など）。受講者層に近い業種がおすすめです。

## 8. 著作権・表現のルール

| 区分 | 扱い |
|---|---|
| 旧資料の文章・質問文・診断項目 | **転載しない**。考え方を参考に、ゼロから書き直す |
| 旧資料の記入内容（事例・個人の回答） | **一切使わない** |
| 実在の企業名・人名・研修名 | **載せない** |
| 一般的な経営フレームワーク（バランススコアカード、マンダラチャート、FMEA、品質機能展開、1on1 など） | 一般的な理論として、自分の言葉で解説する（出典は明記） |
| 診断テスト（リーダーの癖、リーダーシップ診断、仕組み化診断） | 設問を**オリジナルで新しく作る**（旧135問 → 新27問程度に短縮） |

## 9. Webシステム設計

### 9-1. 構成（おすすめ：段階的に育てる）

| 段階 | 内容 | 保存先 | 費用 |
|---|---|---|---|
| **第1段階（今回）** | 学習サイト＋ワーク入力＋自動保存＋印刷／PDF・Excel・JSON書き出し＋読み込み | 各自のブラウザ（書き出したファイルで別端末へ移せる） | 無料（GitHub Pages） |
| 第2段階（任意） | ログイン、クラウド保存、どの端末からでも再開 | Supabase（無料枠あり） | 無料〜 |
| 第3段階（任意） | 講師が受講者の進捗を確認、コメント、グループ学習 | 同上 | 無料〜 |

### 9-2. 画面構成
- **トップ**：全体マップ（20章のすごろく形式）、自分の進み具合（％）
- **章ページ**：左に目次、中央に解説とワーク、入力すると自動保存
- **マイ設計図**：全章の完成物を1ページにまとめて表示し、印刷できる（＝会社の取扱説明書の下書き）
- **講師向け**：各章の「進め方ガイド」（セミナーでの時間配分、問いかけ例）

### 9-3. 技術（保守しやすさを最優先）
- 章の本文とワークの設問は **Markdown ファイル**で管理します。矢部さんが文章を直すときは、テキストを編集するだけで済みます。
- 静的サイト生成（Astro）→ GitHub Pages で公開
- スマートフォン対応

### 9-4. フォルダ構成（予定）
```
shikumi-keiei/
├─ docs/           設計書・講師ガイド
├─ content/
│   ├─ chapters/   00〜20章の本文（Markdown）
│   └─ example/    架空企業の記入例
├─ src/            Webシステムのプログラム
└─ README.md       使い方・公開手順
```
